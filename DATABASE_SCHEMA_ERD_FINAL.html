Project Overview & Architecture

This document describes the complete database schema and Entity Relationship Diagram (ERD) for the E-Commerce Platform. The system is built on Firebase Firestore, a NoSQL document database, providing scalable, real-time data synchronization.

Technology Stack

  • Database: Firebase Firestore (NoSQL)
  • Storage: Cloudinary (Image CDN)
  • Authentication: Firebase Auth + Google OAuth2
  • Backend: Node.js/Express
  • Password Security: bcryptjs (10 salt rounds)

Collections Detail: Users & Products

Users Collection

Manages user accounts, authentication, and profile information. Each user has a unique UUID and email address.

Field Type Constraints Description
id String PK, UUID Unique user identifier
email String UNIQUE, INDEXED Email address (lowercase)
password String Hashed bcryptjs hash (10 rounds)
first, last String Optional Full name
phone String Optional Contact number
address, city, country String Optional Shipping address
createdAt, updatedAt Timestamp SERVER_GENERATED Account timestamps

Products Collection

Maintains product catalog with pricing, inventory status, and images hosted on Cloudinary.

Field Type Constraints Description
id String PK, UUID Unique product ID
name String Required Product title

price, oldPrice Number Required Current & original price

Orders Collection

Tracks customer orders with items, status workflow, and delivery information. Each order is linked to a user via userId.

Field Type Constraints Description
id String PK, UUID Order ID
order_code String UNIQUE Human-readable code
userId String FK, INDEXED Reference to Users
items Array<Object> Required Order line items
totalPrice Number Required Total amount
status String INDEXED, Enum pending, processing, shipped, delivered
paymentMethod String Optional Payment type
createdAt, updatedAt Timestamp SERVER_GENERATED Order timestamps

Key Features

  • Authentication: Email/password or Google OAuth2. Passwords hashed with bcryptjs (10 salt rounds)
  • Image Storage: Cloudinary CDN for product images, external storage reduces Firestore load
  • Real-time Sync: Firebase Firestore provides automatic real-time updates
  • Server Timestamps: All timestamps generated server-side to prevent client clock skew
  • Query Optimization: Strategic indexing on userId, status, category for fast queries
  • Scalability: Firestore automatically scales to millions of documents

🎯 Query Patterns

Get user orders: Orders.where('userId', '==', userId)
Find by category: Products.where('category', '==', category)
Filter by status: Orders.where('status', '==', status)

Data Integrity Rules

  • Emails stored in lowercase for consistency
  • Passwords never stored in plain text (bcryptjs hashing)
  • Timestamps server-generated (Firebase FieldValue.serverTimestamp)
  • Order status follows defined workflow
  • Product items maintain price snapshot at purchase time
  • All IDs are UUIDs for global uniqueness
